# 05 · 脚本与工具说明

## 一、scripts\ 目录

### macrecovery.py

**作用**：从 Apple 服务器下载 macOS 恢复镜像（BaseSystem.dmg）。

**来源**：OpenCore 官方 Utilities。

**用法**：

~~~bash
# 下载指定版本的恢复镜像
python3 macrecovery.py -b Mac-XXXXXXXX -m 0000000000000000 download
~~~

**本次踩过的坑**：

| 参数 | 结果 |
|---|---|
| `-os latest` | 下载到 1 MB 的坏文件（实际是错误响应） |
| 指定具体 build（如 `093-10615`） | 正确下载 848 MB |

**输出**：`com.apple.recovery.boot/BaseSystem.dmg` + `.chunklist`。

### run_system_task.py

**作用**：在 Windows 上以 **SYSTEM 权限** 通过计划任务执行命令。

**为什么需要**：SSH 登录的管理员账户拿不到完整的本地管理员令牌，某些 WMI/存储操作会返回 `0x5 拒绝访问`。

**关键设置**：

~~~powershell
DisallowStartIfOnBatteries = $false   # 否则笔记本用电池时任务被挂起
StopIfGoingOnBatteries     = $false
~~~

## 二、tools\ 目录

### macserial

**作用**：生成格式合法的 SMBIOS 三码（序列号 + MLB），用于 iCloud/App Store。

**平台**：`macserial`（macOS）/ `macserial.exe`（Windows）。

**用法**：

~~~bash
./macserial -m MacBookPro16,3 -n 3
~~~

**输出（3 组）**：

~~~
C02DG1ZKP3XY | C02039401J900001M
C02CP4Z7P3XY | C02019700J900001M
C02CG0E3P3XY | C02012403GU0000JC
~~~

左侧是序列号，右侧是 MLB，**必须成对使用**。

**注意**：

- 生成的是「格式合法」的号码，**不保证 Apple 服务器接受**
- 撞上真实 Mac 的序列号可能触发风控（本次 iCloud 登录失败就与此有关）
- 换序列号后必须**重启**才生效

### ocvalidate.exe

**作用**：校验 OpenCore 配置语法。

**用法**：

~~~
ocvalidate.exe config.plist
~~~

**必须注意**：`ocvalidate` 的版本要和 `OpenCore.efi` 版本一致！

| 情况 | 结果 |
|---|---|
| 0.8.8 配置 + 1.0.7 校验器 | 报一堆不存在的字段 |
| 版本一致 | 全绿 |

## 四、installer\ 目录

| 文件 | 说明 |

|---|---|
| `BaseSystem.dmg` | macOS Sequoia 15.6.1 恢复镜像（848 MB） |

| `BaseSystem.chunklist` | 完整性清单 |

| `config-EFI-0.8.8.plist` | 当前使用的 OpenCore 配置样本 |

### 怎么用这个镜像

**方法 A：写入 U 盘（本次用的方法）**

~~~
1. 用 7-Zip 打开 BaseSystem.dmg（-tDmg），提取 4.hfs

2. 把 4.hfs 写到 U 盘分区 1（偏移 1 MiB）
~~~

**方法 B：恢复环境里直接用**

~~~bash
hdiutil attach BaseSystem.dmg
~~~

**注意**：这是**恢复镜像**，只含 ~850MB 的恢复环境。

装系统时 macOS 会从 Apple 在线下载约 **12 GB** 本体，所以**必须联网**。

### 直接使用

~~~bash
sudo diskutil mount disk0s1
sudo rm -rf /Volumes/EFI/EFI
sudo cp -R ./EFI /Volumes/EFI/
sudo diskutil unmount disk0s1
~~~
